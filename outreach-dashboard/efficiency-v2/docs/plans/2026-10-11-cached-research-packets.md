# Reuse evidence leads, not eligibility

Local preflight takes approximately 0.18 seconds; further micro-optimization is
not the main outreach bottleneck. Pending packets currently discard clean research
matches, requiring the operator to reopen raw cache files or repeat discovery.

Attach a bounded cache context to the existing pending packet: up to six primary
source leads, three contact candidates, observed scores and conflict flags. Match
explicit company/domain/recipient identities, never transfer subsidiary contacts
through a group-only match. Preserve all permanent group locks. Cache values remain
untrusted leads; no cached score, public email or source alone authorizes sending.

Retain full fresh preflight, IAB, template 2, live agency/CRM/mailbox checks, strict
ICP above 70, serial one-send receipt verification and immediate permanent recording.
Review score provenance against canonical country inputs before new sends; observed
cached scores are not recomputed or endorsed by this optimization.

Alternatives rejected: another faster local index has negligible end-to-end impact;
parallel email sending risks unknown outcomes. Batch cloud updates before handoff
instead of redeploying after every research item. No artificial packet fill wait.

Test identity isolation, bounds, conflicts, secret URLs, fresh-cache visibility and
unchanged history guards. Publish safe code to GitHub and exact tested source to the
existing owner-private Site. Measure avoided cache-file revisits and output bytes,
not an unmeasured promise about the time required to send 100 qualified messages.
