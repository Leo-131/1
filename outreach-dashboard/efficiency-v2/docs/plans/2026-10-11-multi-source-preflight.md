# Multi-source, evidence-first preflight

One invocation accepts repeated `--candidates <file>` arguments. Pool discovery
sources before a single union-history/research pass; retain the maximum 100-row
pending batch and concise 10-row default execution packet. This removes repeated
history reads when several provider seed files are processed in the same round.

Existing direct-company/domain source and contact leads are stably ordered first
for live verification. Conflicting contacts/scores do not get this priority.
Scores do not set priority or authorize sending. All history, group, unknown-send,
failed-source and daily agency/live-mailbox gates remain unchanged. No network,
model, mail send or waiting is introduced by the planner.

The browser uses the same evidence-first ordering. Cached leads are not trusted
eligibility, and the webpage does not become an autonomous mail executor.

Verify multi-source group dedup, fresh receipts between invocations, cache
conflicts, stable order and cap behavior. Benchmark pooled vs separate local
preflights only; do not describe local timing as end-to-end outreach acceleration.
